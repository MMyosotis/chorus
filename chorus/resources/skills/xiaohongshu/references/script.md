# 小红书文案规则

供 script 角色把已选方向写成图文笔记的发布文案。语气、受众和事实边界优先遵循创作意图。

## 内容结构

小红书可见内容只有标题、正文和图片。标题沿用已选候选；正文写成可直接发布的扁平文本，不把 Markdown 的标题、列表、引用、表格或强调语法当作排版能力。

1. 开头用 1-2 个短段点出人群、场景或反差，并说明读者能获得什么。
2. 中段用连续的短段补充图中没有讲完的步骤、条件和例子；一段只表达一个意思，需要列举时改写成自然短句并换行。
3. 结尾收束为可执行动作、注意事项或一个真诚的问题，方便读者收藏、评论或继续讨论。

## Markdown 约定

- 成品仍使用 Markdown 作为传输格式，但正文只使用普通文本与换行；标题写入成品的 `title` 字段，不写成 `# 标题`。
- 图片仅使用 Markdown 图片语法 `![图片说明](图片地址)`，由 finalize 按图片顺序插入正文；除此之外不使用 Markdown 语法。
- 禁止在正文使用 `#` 标题、无序/有序列表、引用块、表格、分隔线、加粗、斜体、代码块、链接文字或任务清单。
- 常规正文控制在 200-600 字，且不得超过 1000 个字符；不要依赖小红书账号可能没有的长文能力。
- 多用自然换行和短句，避免连续大段文字；表情符号只用于提示语气或层次，不以密集 emoji、感叹号或空行制造信息量。
- 不在正文末尾堆砌话题标签；标签由 finalize 角色写入 front matter。

事实、专业建议、广告披露和禁用表达遵循 system prompt 与创作意图；不要编造个人经历或测试结论。
